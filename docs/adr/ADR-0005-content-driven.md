# ADR-0005: コンテンツ駆動設計

- 状態: Accepted
- 決定日: 2026-07-24

## 背景

ワタリEAでは、Markdown、YAML、画像をイベント単位で管理し、データからページを生成している。

アマノPJでも、制作実績、経歴、プロフィールなどを構造化データとして管理する可能性が高い。

ただし、イベント固有スキーマをASCへ持ち込むと汎用性が失われる。

## 決定

ASCは、Git管理された構造化コンテンツから静的ページを生成するための基礎機構を提供する。

具体的なCollection、スキーマ、ページ構成は派生プロジェクトが定義する。

## 理由

- コンテンツと表示を分離できる
- Git上で差分管理しやすい
- 管理画面から編集しやすい
- 同じ基盤を異なるドメインへ適用できる
- 固有スキーマをASCへ固定しなくてよい

## 影響

- ASCは特定のCollection名を前提としない
- Section Rendererを導入する場合も、登録型または拡張可能な設計とする
- イベント用Section、ポートフォリオ用Sectionは各派生側へ置く
- 共通スキーマは最小限に保つ

## 代替案

### ASCで統一された汎用ページスキーマを強制する

各サイト固有の表現力を損なうため不採用。

### ページをすべてAstroファイルへ直接記述する

小規模サイトでは有効だが、GitOps編集、検証、管理画面との連携が弱くなるため標準方式にはしない。
