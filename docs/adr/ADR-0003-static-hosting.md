# ADR-0003: 静的ホスティング前提

- 状態: Accepted
- 決定日: 2026-07-24

## 背景

ASCは、ポートフォリオ、イベント告知、サービスLPなど、静的生成で成立するサイトを主対象とする。

SSRや常時稼働サーバーを前提にすると、構成、費用、保守、障害要因が増える。

## 決定

ASCはAstroの静的出力を前提とし、生成物を静的ホスティングサービスへ配信する。

SSR、データベース、常時稼働APIが中心要件になった場合は、別プロジェクトまたは別基盤として扱う。

## 理由

- 配信構成が単純
- 運用コストが低い
- 高い可搬性を維持できる
- CDN配信と相性がよい
- セキュリティ上の攻撃面を減らせる

## 影響

- 動的機能はビルド時処理または限定的な補助Functionとして設計する
- ランタイム処理をASCの中心に置かない
- SSRへの移行はASCの通常アップデートではなく、別基盤の検討対象となる

## 代替案

### Astroのhybridまたはserver出力を標準にする

対象範囲が広がる一方で、ASCの責務と配信環境が複雑になるため不採用。
