# ADR-0001: プロジェクトの責務

- 状態: Accepted
- 決定日: 2026-07-24

## 背景

ASCは、既存のイベントサイトから共通機能を抽出し、ポートフォリオサイトやサービスLPにも再利用する目的で開始された。

既存実装には、静的サイト共通機能とイベント固有機能が混在している。

責務を定義しないまま抽出すると、ASCがイベントCMS、UIライブラリ、Webアプリケーション基盤を同時に抱える可能性がある。

## 決定

ASCを、GitOpsを前提とした汎用的な静的サイト生成基盤とする。

ASCは、静的サイトに共通する設定、レイアウト、SEO、テーマ、コンテンツ処理、Git操作、デプロイ補助を扱う。

イベント、出演者、タイムテーブル、経歴、制作実績などの固有ドメインは扱わない。

## 理由

- 再利用可能な責務を明確にできる
- 派生プロジェクトの固有性を維持できる
- ASCの肥大化を防げる
- SSRやDBが必要なプロジェクトと区別できる

## 影響

- ワタリEAの全機能をASCへ移すことはしない
- アマノPJ固有のモデルもASCへ追加しない
- 共通化できるコードであっても、固有ドメインへの依存が強い場合は派生側に残す

## 代替案

### イベントサイト専用コアとする

アマノPJや将来のLPへ再利用しにくいため不採用。

### 汎用Webアプリケーション基盤とする

責務が広すぎ、静的サイト向け基盤としての単純さが失われるため不採用。
