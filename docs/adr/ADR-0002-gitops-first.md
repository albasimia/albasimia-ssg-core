# ADR-0002: GitOpsファースト

- 状態: Accepted
- 決定日: 2026-07-24

## 背景

ASCの派生プロジェクトでは、コンテンツと設定をGitで管理し、pushを起点としてビルド・公開する運用を想定している。

管理画面を導入する場合、独立したデータベースを正本にすると、Git上の状態との二重管理が発生する。

## 決定

Gitをコンテンツと設定の正本とする。

管理画面や補助ツールは、GitHub上のファイルを読み書きするインターフェースとして設計する。

## 理由

- 変更履歴が残る
- 差分確認ができる
- ロールバックしやすい
- レビュー可能
- 静的ホスティングと接続しやすい
- ベンダーや独自DBへの依存を減らせる

## 影響

- 保存処理ではCommit単位を意識する
- 競合検知が必要になる
- 大規模な高頻度更新には向かない
- GitHub APIの制約を考慮する必要がある
- 管理画面は正本ではなく編集手段となる

## 代替案

### 管理画面専用データベースを正本とする

Gitとの二重管理が発生し、静的サイトとしての単純さが失われるため不採用。

### Headless CMSを正本とする

有効な構成ではあるが、ASCのGitOpsファーストという目的から外れるため標準にはしない。
