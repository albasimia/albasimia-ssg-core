# ADR-0004: 派生プロジェクト方式

- 状態: Accepted
- 決定日: 2026-07-24

## 背景

ASCは、ワタリEAとアマノPJを最初の利用例とする。

両者はサイト構造、コンテンツモデル、ビジュアル、目的が異なる。

単一リポジトリ内へ全サイトを置くと、共通基盤と固有実装の境界が曖昧になる。

## 決定

ASCを独立した公開リポジトリとして管理し、各サイトを別の派生プロジェクトとして管理する。

初期の派生プロジェクトは次の2つとする。

- `catharsiswatari-events`
- `amano-pj`

## 理由

- 各サイトの独立性を維持できる
- ASCの公開範囲を明確にできる
- 固有コンテンツやSecretの混入を防げる
- ASC自体をポートフォリオ実績として提示できる
- 実利用から共通化の妥当性を検証できる

## 影響

- ASCと派生プロジェクト間のバージョン整合が必要になる
- 変更時には複数サイトで検証する
- ASCへ機能を追加する際は、派生プロジェクト固有の都合だけで判断しない

## 代替案

### Monorepo

初期段階では構成と公開範囲が複雑になるため採用しない。将来、運用上の必要性が明確になった場合は再検討する。

### テンプレートの複製のみ

共通修正を各サイトへ反映しにくく、基盤として育てられないため不採用。
